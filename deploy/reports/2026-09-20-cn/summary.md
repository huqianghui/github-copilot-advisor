## 时延与并发

### 先明确计时边界

**Agent turn 包含 Model call 和工具执行。** 两者分别埋点，不是互不重叠的阶段。
Agent 覆盖核心程序的轮次协调、规划、缓冲会话读取、消息准备、聊天/工具循环、
答案后处理/评估和缓冲会话写入。它不包含 worker 的持久化归档读取/提交、
首次组件构造、最终回复渲染和回调发送。

在常见的两次调用路径中，第一次聊天补全请求工具，KB 与 GitHub 检索在工具内部并行，
第二次聊天补全根据结果回答。这些操作都在 Agent 内部。
`model` 计时一次聊天 SDK 调用，不包含工具执行或 embedding；KB 阶段包含自身的 embedding 操作。
暖态样本组 A 的 100 个 Agent 观测均值为 6,525.426 ms，
200 个模型观测的**每次调用**均值为 3,019.782 ms；这些不是可以相加的独立总时长。

所有阶段（`ingress`、`queue_wait`、`worker_init`、`auth`、`connection`、`history_setup`、
`history_read`、`history_commit`、`synthetic`、`agent`、`kb`、`github`、`web`、
`model`、`render`、`send`）的完整含义、嵌套关系图和实现依据，
见[阶段定义与计时边界](stage-definitions.md)。

- 完整回复时延终点是观察器接收完整回调正文的时刻；ACK/typing 不是完成，也不是 Teams 客户端时延。
- 并发数表示未完成的**逻辑问题数**，不是 HTTP 连接、模型调用或 Azure 副本数；HTTP 202 不释放槽位。
- 阶段观测是可能重叠的经过时间。模型按调用统计，覆盖率按不同问题统计。
  不要累加阶段，也不要对其百分位数进行加减。
- 成功时延、降级回复和删失任务分别统计。`answers/s` 包含成功与降级，
  `successes/s` 只包含成功；分母都使用包含排空等待的实际窗口。
